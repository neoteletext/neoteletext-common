## 1. Engine `neoteletext-web`

### 1.1 HTTP/1.1 response parsing (`http.rs`, `http/head.rs`)

**Checked and sound.** Status line read strictly (`HTTP/` DIGIT `.` DIGIT, three-digit code, reason phrase of field text only); bare LF accepted as a line end but CR anywhere else rejected; field names token-only with no space before the colon; field values HTAB/SP/VCHAR/obs-text only, so NUL, CR, LF and DEL are refused; obsolete line folding refused (`LeadingWhitespace`); field count ≤ 64; head size bounded by the caller's buffer through `HeadCollector`, which looks at each byte once; `Content-Length` must be ≤ 10 decimal digits, and duplicates must agree, `Content-Length: 5, 5` refused; `Transfer-Encoding` must be exactly `chunked`, once, and only on HTTP/1.1; `Transfer-Encoding` with `Content-Length` refused (`AmbiguousFraming`); `Content-Encoding` other than `identity` refused; chunk size ≤ 8 hex digits with no whitespace, extensions bounded by the 256-byte line buffer, chunk data terminated by exact CRLF, `BadChunk` on any deviation; chunked and `Content-Length` bodies capped before data is copied; `Retry-After` capped at 600 s; `Sec-WebSocket-Accept` must be exactly 28 bytes. The proptest `never_panics` and the `http` fuzz target reach all of this. The three classic desync vectors (CL+TE, duplicate CL, TE with a non-chunked coding) are all refused.

**W5 — 1xx interim responses fail the exchange (Low).** `parse_head` returns `HttpError::Status` for any status in 100..200 other than 101 (`http.rs:323–325`), and `fetch_head_complete` abandons the fetch (`agent.rs:1668–1671`). RFC 9110 §15.2.1: "A client MUST be able to parse one or more 1xx responses received prior to a final response". `103 Early Hints` is emitted by common CDNs and by nginx/h2o front ends for ordinary files. Probe D: `parse_head(b"HTTP/1.1 103 Early Hints\r\nLink: </x>; rel=preload\r\n\r\n")` → `Err(Status)`. Effect: every page of such a service fails. Fix: in `fetch_received`/`push_received`, when a complete head has status 100..200 and the exchange is not a WebSocket upgrade, reset the collector and keep reading; treat only a 1xx *after* the final head as a desync.

**Info.** A response beginning with an empty line (`\r\n\r\nHTTP/1.1 200 …`) ends the head at its fourth byte and is `Malformed`, though RFC 9112 §2.2 lets a client ignore leading empty lines; no server does this. Trailer lines are limited to 256 bytes each (`MAX_CHUNK_LINE`), stricter than RFC 9112 §7.1.2, and their count only by the 30 s exchange deadline. Cookies on a 101 or a redirect are stored before the status check (`agent.rs:1660` before `1668`), which RFC 6265bis permits.

### 1.2 URL parser (`url.rs`)

**Checked and sound.** ASCII 0x21–0x7E only; `\` and `#` refused outright; schemes limited to http/https/ws/wss; `@` anywhere in the authority refused (`http://good.example@evil.example/`); the authority ends at the first `/` or `?`, so `http://evil.example?@good.example/` has host `evil.example` — correct; IPv4 strict dotted decimal with no leading zeros, and any host whose last label is numeric or `0x…` must parse as IPv4 (closes `0177.0.0.1`, `0x7f000001`, `2130706433`, `127.1`, `1.2.3.4.5`); `127.0.0.1.` refused (empty last label); IPv6 in brackets with one `::`, at most 8 groups, 4 hex digits each, an IPv4 tail, zone identifiers refused; port 1–65535 with no leading zero; DNS labels 1–63 of alnum/hyphen not starting or ending in `-`, host ≤ 253; percent-encoding checked for two hex digits but never decoded, so `%2e%2e` and `%2F` stay literal (`http://a.b/%2e%2e/%2e%2e/etc` is accepted and sent as written, which the channel address rules then refuse because `%` is not unreserved). `remove_dot_segments` was traced on `/a/b/../c`, `/..`, `/../../x`, `/a/.`, `/a/..`, `/a//../b`, `/..x`, `/a%2F../b`: all RFC 3986 §5.2.4 results. `join` was traced on every RFC 3986 §5.4.1 normal example the schemes allow, plus `//evil.c/x` (network-path reference, correctly a new host, then subject to the redirect/channel policy), `///x` (refused, empty host), `..//x`, `?`, `:x`. All offsets are `u16` and the text ≤ 2048 so no truncation. Probe F printed each result.

**Info.** Origins compare IPv6 hosts by their text, not their value (`[::1]` ≠ `[0:0:0:0:0:0:0:1]`, asserted by `url.rs` tests). Fail-closed, but the secure-host memory (REQ-SEC-007), the cookie host and the confirmed-origin table are split between spellings. Normalising the stored host text to RFC 5952 would remove the split.

### 1.3 Cookie jar and `Set-Cookie` (`cookie.rs`) against RFC 6265bis (draft of September 2026)

**Checked and sound.** §5.6 step 1 (any %x00-08 / %x0A-1F / %x7F aborts, HTAB allowed); name/value split at the first `=`, OWS trimmed, both-empty refused, name+value ≤ 4096; attribute values > 1024 ignored (not the cookie); `Max-Age` grammar (optional `-`, digits only; ≤ 0 → earliest date, deletion); `Expires` by the §5.1.1 algorithm with the day/month/year/time order, two-digit years, 1601 floor, impossible dates refused, pre-1970 clamped, 400-day cap on both; `Domain` ignored so every cookie is host-only, and its presence still breaks `__Host-`; `Path` must start with `/` else the §5.1.4 default path; `Secure` over plain HTTP refused, and §5.7's rule that plain HTTP may not replace or delete a `Secure` cookie whose path covers the new one (`path_matches(new, existing)` is the right direction); `__Secure-`, `__Host-`, `__Http-`, `__Host-Http-` checked case-insensitively, and a nameless cookie whose value starts with a prefix refused; `SameSite=None` without `Secure` refused; `Cookie` header longest-path-then-oldest; per-host then total eviction, expired first then LRU; the arena compaction (`remove`) was traced and keeps the other records' offsets right; the `cookie` fuzz target reaches `store`, `header_for` and the date parser. There is no public-suffix handling because there is no `Domain` handling — the right trade for a host-only jar.

**W3 — Export/import widens a long path to `/` and stops at the first bad record (Low).** `import_one` rebuilds a `Set-Cookie` header `name=value; Path=<path>; Max-Age=…` and stores it through `store(…, "/", …)` (`cookie.rs:723–737`). `parse_attributes` ignores any attribute value over `MAX_COOKIE_ATTRIBUTE_VALUE` = 1024 (`cookie.rs:839`), so a saved path longer than that is dropped and the default path of the request path `/` applies: the cookie comes back scoped to the whole host. A path that long arises from the §5.1.4 default path of a request path over 1024 bytes, which `MAX_URL_LENGTH` = 2048 allows. Probe C: a cookie set by `/channel/ddd…(1100)/page` was sent only inside that folder before export and to `/other` after import (`RESULT C: … true`). A channel's folder path is ≤ 256 (`channel::MAX_FOLDER_PATH`) so a channel-scoped cookie cannot have this path from the agent itself, but `store` is public and the saved file is read as untrusted. Separately, `import_one` returns `None` for an expired record (`expires.checked_sub(now)?`, line 722) and `import` treats that as malformed and stops (`cookie.rs:686–688`): one expired cookie at the top of the file loses every record after it. Fix: write the path into the rebuilt record only when ≤ 1024 and otherwise call a path-taking internal store; skip, do not stop at, an expired record.

### 1.4 Server-sent events (`sse.rs`) and WebSocket framing (`ws.rs`)

**Checked and sound (SSE).** HTML §9.2.6 interpretation: BOM, CR/LF/CRLF line ends split anywhere, comment lines, field name matching with a 5-byte name buffer (`eventually:` ignored), one leading space stripped, `data` lines joined with LF and the last LF removed, no dispatch without data, `event` type reset per dispatch, `id` with NUL ignored, `last_event_id` set at dispatch, `retry` ignored by design, data bounded by the push limit (`TooBig` abandons the stream, by design). Linear per byte. Fuzzed (`sse`).

**W6 — `Last-Event-ID` is written with the server's raw id bytes (Low).** `SseParser::value_byte` rejects only NUL in an id (`sse.rs:250`); `push_connected` writes it as a header value (`agent.rs:2365–2368`). CR and LF cannot occur (they end the line), so there is no header injection, but 0x01–0x1F, 0x7F and non-UTF-8 bytes go out verbatim. Probe G: `id: a\x01b\x7f\xff` produced the reconnect request `Last-Event-ID: a\u{1}b\u{7f}\xff`. RFC 9110 §5.5 forbids CTLs in a field value; a proxy or a strict server answers 400, so the reconnection fails and, since the id is kept, keeps failing until the service is reopened. Fix: treat an id holding a byte < 0x20, 0x7F or invalid UTF-8 as invalid, as NUL is.

**W7 — The final body step's data never reaches the SSE parser (Low).** `push_events` returns `None` on `step.done` before the `while !data.is_empty()` loop that feeds `step.data` (`agent.rs:2602–2605`). With `Content-Length` framing the last step carries data and `done` together; that data is lost. Observed in Probe G's first run: an event whose dispatch fell in the last 7-byte read never set `last_event_id`, so no `Last-Event-ID` was sent. Fix: feed `step.data` first, then handle `done`.

**Checked and sound (WebSocket).** RSV bits and a masked server frame refused; opcodes 3–7 and 0xB–0xF refused; control frames must be FIN with payload ≤ 125; non-minimal 16- and 64-bit lengths and bit 63 refused; a continuation without a start and a new data frame inside a fragmented message refused; interleaved control frames allowed; text validated as UTF-8 at message end; close payload of 1 byte refused and its reason validated; the message buffer is the only memory, with `skipping_oversized` draining a long message byte by byte; handshake checks status 101, `Upgrade`, `Connection: Upgrade`, the exact accept value and no unrequested extension/subprotocol; pongs echo at most 125 bytes. Fuzzed (`websocket`).

**Info.** A ping flood produces one `Output::Send` per ping with no rate limit in the agent; the port's send buffer is the backstop. The push WebSocket's `Close` is answered and the connection reconnects with backoff: a server closing with 1000 every time costs the client one reconnection per 60 s at most.

**Checked and sound.** `contents.rs`: 64 KiB and 1000 lines checked before iteration; each line printable ASCII plus TAB; kinds `s`/`p`/`x` with exact field counts; page three decimal digits in magazines 1–8; date `YYYY-MM-DD` with range checks; targets `name:mpp` or a channel folder/page address; titles cut at 32 bytes (ASCII, so no boundary issue); duplicate pages by an 800-bit set. `json.rs`: whole-input UTF-8 check first, depth ≤ 16, RFC 8259 number grammar, control characters in strings refused, escapes and surrogate pairs validated, `decode_into` offsets traced for the surrogate case, trailing data refused, `equals` on a decoded key longer than 64 bytes is simply false. `descriptor.rs`: required members, duplicates, unknown members, wrong types all reject the whole document; names refuse < 0x20 and 0x7F; `page_template` placeholders limited to `{m}` `{pp}` `{mpp}` `{sub}` and refused in the authority (`1.2.3.{pp}`, `//p{m}.example`); every expansion has the same length so one trial expansion proves them all; addresses resolved through the strict joiner with the HTTPS-descriptor-no-plain-address rule; `form_origins` ≤ 8, services ≤ 16, aliases ≤ 16, all in fixed buffers; channel settings refuse `page_template` and require push on the channel's origin. `channel.rs`: folder rules checked on the address *as written* (so `..`, `.`, `%2F`, `//` and `#` never reach the parser's repair), ≤ 8 segments of ≤ 64 unreserved bytes, page file names capital-hex only, `is_t42` requires Hamming-valid addresses on every packet, `is_tti` a `PN` line. **Info.** Descriptor names and display names allow C1 controls (U+0080–U+009F) and Unicode bidi controls, which `policy::is_safe_output_char` exists to filter: it is the port's duty to apply it before terminal or window output.

### 1.8 Agent: redirects, forms, push, cookies in context (`agent.rs`)

**W1 — A channel's push handshake `Set-Cookie` is stored without the channel scope (Medium).** REQ-WEB-026: "A cookie set by a response to a request inside the channel's folder belongs to that channel. A `Path` attribute outside the folder, including the default path, shall be narrowed to the folder… never with another channel's requests, even on the same origin." `fetch_head_complete` passes `scope = channel.path()` to `store_response_cookies` (`agent.rs:1658–1660`), but `push_head_complete` passes `None` (`agent.rs:2461–2471`), for both the WebSocket upgrade and the SSE response. A channel's push may be "anywhere on its origin" (REQ-WEB-026 Push), and its handshake response is still a response the channel controls. Probe A: channel `http://site.example/a/` with `channel.json` naming `ws://site.example/push`; the 101 carried `Set-Cookie: planted=1; Path=/`; the jar then gives `planted=1` for `/b/100.tti` and for `/`, while a `Set-Cookie: page=1; Path=/` from `/a/100.tti` was correctly narrowed to `/a/`. Effect: on a shared host (REQ-WEB-026's reason: "another folder is often another person") channel A plants a cookie that every other channel on the host receives — a session-fixation primitive against a neighbour's forms, and a tracking cookie across channels. Fix: `store_response_cookies(store, head_bytes, host, path, self.channel.as_ref().map(Url::path), …)` in `push_head_complete`, exactly as the fetch path does. A test with two channels on one origin and a push-set `Path=/` cookie belongs beside the existing REQ-WEB-026 tests.

**W2 — A form submission is re-posted wherever a permitted origin redirects it (Medium).** `form::destination` applies REQ-WEB-008/REQ-SEC-009 (`policy::may_submit`) once, before the first request (`agent.rs:2133`). `redirect` keeps the method and body on 307/308, skips the channel rule for `Purpose::Form` ("Forms keep their own rule below") and the only rule below is the `Site` downgrade to `CrossOriginForm` (`agent.rs:2008–2019`); the first-submission confirmation (`confirm_first_submission`, REQ-SEC-009) and the plain-HTTP warning (REQ-SEC-008) are decided in `submit` for the original target only (`agent.rs:2185–2200`). Probe E: a page on `tt.example` with `form_origins: ["http://forms.example"]`; the POST to `forms.example` answered `307` with `Location: http://third.example/collect`; `third.example` received `POST /collect … secret=hunter2&ttx_token=tok` with no `ConfirmSubmission` event for it. The HTTPS→HTTP downgrade rule does hold on redirects (`agent.rs:1990`), and the permitted origin already holds the values server-side, so the gain to an attacker is the bypass of the confirmation and of the allowlist's *visibility* to the viewer, plus the `ttx_token` reaching an origin the page never named. Fix: on a redirect of `Purpose::Form`, re-check `policy::may_submit(page_origin, next.origin(), permitted)` and the channel rule, failing with `FormRefused::Origin` (or convert 307/308 to GET without the body, as 303 is handled), and re-run the confirmation when the origin changes.

**W4 — An empty or non-UTF-8 `Location` re-requests the same address (Low).** `head.location` is a `TextBuf<2048>` of the raw value; `as_str()` of non-UTF-8 is `""`; `exchange.url.join("")` is the base itself (RFC 3986 §5.2.2 with an empty reference). `redirect` then starts a new exchange immediately, outside the fetch-interval limit, until `MAX_REDIRECTS` (`agent.rs:1973–1987`, `2020–2026`). Probe B: one `FetchPage` produced six `GET /p/100` requests and `TooManyRedirects`. Effect: ×6 request amplification per page against the origin, and the viewer sees a failure instead of the 3xx page. Fix: an empty `Location`, or one that resolves to the same address with the same method, is `Failure::BadRedirect`.

**Checked and sound.** Redirect limit 5; `Location` through the strict joiner; WebSocket schemes refused as redirect targets; HTTPS→HTTP refused for every purpose; blocked peers refused both by literal before connecting and by the connected peer address (DNS rebinding covered); 303 and 301/302-on-POST become GET with the body cleared; bytes after a complete response close the connection (no pipelining desync); a server-closed kept-alive connection is retried once for GET only; `Retry-After` capped; `Clear-Site-Data` only over HTTPS and only for the responding host; the cookie header is written with a reserve so the body always fits; the SSE subscription query is built from page numbers the agent wrote; push `Binary` messages must be a multiple of 42 bytes; `send_input` refuses anything over `INPUT_MESSAGE_MAX`. The replay tests (`tests/agent_replay.rs`) cover most of the above.

### 1.9 zxnet live-feed reader (`zxnet.rs`)

**Checked and sound.** Channel identifiers: strict base64, a JSON array of exactly three printable strings without commas, host without `/` or `?`, path starting with `/`, rebuilt as `wss://host/path` through the strict parser. Server messages: each a JSON array named by a plain string; `header`/`row`/`bsdp` payloads must decode to exactly 40 bytes; `row` numbers 1–31; magazines 0–8; packets rebuilt with a Hamming-coded address the engine writes; `clock` and `initialpage` decoded into fixed buffers with length checks; `pageExists` indexed into a 256-byte bitmap with `magazine.index() ≤ 7` and `page ≤ 255`; oversized messages (the ~88 KB `channelSettings`) skipped by the draining reader; five reconnection attempts; 5 s inactivity. The header cross-check reports disagreement rather than trusting either side. Not fuzzed (gap).

## 2. Engine `neoteletext-formats` and `neoteletext-core` (delegated review, checked)

**No exploitable defect found.** Both crate roots deny `indexing_slicing`, `arithmetic_side_effects`, `unwrap_used`, `expect_used`, `panic`, `unreachable`, `todo`, `unimplemented`. All 61 `#[allow(clippy::…)]` sites were listed; those that re-enable a panicking construct are either compile-time const evaluation (`ecc.rs:105` Hamming 8/4 table, `colour.rs:41`, `charset/tables.rs:1317`, `render.rs:107` — a fault fails the build, never runs) or `#[cfg(test)]` modules. None is on a runtime path that reads untrusted bytes.

**Formats, checked and sound.** `t42.rs`: fixed 45-byte unit buffer, resynchronisation by bounded `rotate_left`, offsets reported. `transport/reader.rs`: PID/adaptation/continuity masked; `adaptation_field_length` up to 255 gives `payload_start` past the 188-byte packet → `None` → `BadAdaptationField`; sections capped at 1024 and longer refused; PAT/PMT/descriptor loops advance by a fixed minimum; CRC-32 checked before use; a continuity break aborts the PES in progress so no data crosses PES boundaries; compaction is a bounded copy. `pes.rs`: byte-at-a-time FSM with one data unit in a `[u8; 257]` buffer; `data_identifier` and framing code checked; an unbounded stream is ended, not followed. `sliced.rs`: fixed 64-byte records with bounded word reads. `edittf.rs`: bounded unpacking, base64/hex length-capped, X26/X27/X25 fields length-checked, `checked_shl`. `ep1.rs`: file ≤ `EP1_MAX_BYTES`, declared sizes checked both ways, enhancement count `checked_div` then `min(EP1_MAX_PACKETS)`. `bdf.rs` and `bdf/`: file ≤ 256 KiB, line ≤ 512, ≤ 64 properties, ≤ 1024 chars, `ENCODING` must be a Unicode scalar value, BBX within the fixed cell, bitmap rows exactly four hex digits with zero pad bits, sorted insertion by `binary_search` and bounded `rotate_right`, `checked_*` integer parsing, glyphs outside the cell refused. `tti.rs`/`page.rs`: 512-byte line buffer, arguments through 8-digit-capped `decimal`/`hex` with `try_from`, `Text<N>`/`FixedVec` bound every stored text and list, form field column/width bounds checked. `dump.rs`: exactly 960 or 1000 bytes. `detect.rs`: detection window capped, a full window forces a decision.

**Core, checked and sound.** `ecc.rs`: Hamming 8/4 through a const table with `.get().unwrap_or(Uncorrectable)`; Hamming 24/18 SECDED with syndrome > 24 → uncorrectable and the correction shift bounded to ≤ 23; no double error accepted as clean. `packet.rs` and `packet/`: a header with any uncorrectable page/subcode/control nibble is `BadHeader`, so a corrupt header cannot open a wrong page (decision E.7); designation codes range-checked; triplet and colour-word bit offsets (`28 + 16×12 = 220` of 234 bits) stay inside the stream and out-of-range reads give `None`. `acq.rs`, `acq/enhancement.rs`: stores keyed by (address, subcode)/(address, s1), eviction may return `None`, merge/erase index-safe, the hint list bounded at 128 with dedup. `enhance.rs`: explicit stack of depth 4, per-type invocation cap 127, open-area caps 15, total steps bounded by `MAX_WALK_STEPS` (asserted by the `enhancement` fuzz target), REQ-L25-050 (row 0 columns 0–7) enforced in `placeable`, no state across runs. `objects.rs`: prescan bounded by `OBJECT_BODY_TRIPLETS`, pointers into pointer packets refused (decision E.51). `charset/`: every lookup is `code.checked_sub(SPACE).and_then(table.get).unwrap_or(' ')` or a `find`; `char::from_u32(…).unwrap_or(REPLACEMENT_CHARACTER)`; the receiver status columns are redrawn in the fixed English set (REQ-SEC-005), so a hostile national-option page cannot rewrite the page number. `level1.rs`/`level15.rs`: row FSMs index-safe, row 0 columns 0–7 and column ≥ 40 refused in `write`. `fsm.rs`: total transition tables. `nav.rs`/`forms.rs`: `step_stored` bounded to 800, history in `FixedVec`, `parse_int`/`valid_date`/`matches_pattern` all `checked_*` and length-bounded, `rotate_right` guarded. `service.rs`: MJD→civil date entirely in `checked_*`.

**Probe** (`…/A4-probes/formats/probe/`, path dependencies, own target dir): TS packets of all three sizes with `adaptation_field_length = 0xFF`; PAT sections claiming `section_length = 0xFFF`; a raw PES with an unbounded packet and a data unit claiming length 255; an edit.tf line with the full 1167-character payload plus a 16-packet X26 field; a Level 3.5 page whose local X/26 is 16 packets of nothing but Active-object invocations. Output: `no panic` for every case; `enhancement walk: 208 steps <= MAX_WALK_STEPS`; `ALL PROBES PASSED`.

**Fuzz coverage.** `formats` drives every reader through `AutoReader` in attacker-chosen chunk sizes; `packets`/`enhancement` drive the decoder, L1/L1.5 and the full 2.5/3.5 walk and assert the step bound; `bdf`/`bdf_convert`, `tti_enhancement`, `channel_log` reach the font and TTI readers. Gap: no target feeds crafted 188/192/204-byte packets to `TsReader` directly with controlled PID/CC/adaptation fields, so continuity-counter and section-reassembly edges are explored only through format detection.

**Info.** `check_continuity` accepts an unlimited run of duplicate-counter packets (ISO 13818-1 allows one); they are dropped before the PES parser, harmless for teletext. The PNG writer (`neoteletext-image`) encodes the decoder's own grid and parses nothing untrusted; it was not reviewed as a reader.

## 3. Browser `native/` (delegated review; B1–B6 re-read by me at the cited lines, B4 and B5 by probe)

### B1 — High (Linux), Medium (macOS): a compromised updater can change a staged version after the launcher verified it
Design: installation-and-updates.md section 5 (a compromised updater "cannot get a version run"); installation-and-updates-security.md 4a closed exactly this on Windows by copying. Code: `launcher/src/lib.rs:331–345` (`Launcher::accept`, Linux arm): `update::accept::accept(&from, …)` verifies the files in place under `staging/<v>`, then `std::fs::rename(&from, &installed)` moves the same inodes into `versions/<v>`; Windows uses `copy_in` (`lib.rs:363–376`: copy, verify the copy, rename the copy); macOS exchanges the staged bundle itself (`lib.rs:321–329`, `macos.rs:55–58`). The updater's sandbox grants `staging/` read+write: `confine/src/linux.rs:159–166` (Landlock `AccessFs::from_all` beneath the writable folder for `Role::Updater`) and `confine/src/macos.rs:126` (`file-write* (subpath staging)`); both are checked at open, so a descriptor opened for writing before the rename stays writable after it. Nothing ends a lingering updater: `launcher/src/start.rs:86–94` kills the process group only on the health timeout; the updater's only exit path is stdin EOF (`tuf/updater/src/main.rs:71–75`). Hostile input: an updater taken over through what it parses (threat 4 of the security analysis) stages a genuine signed release, keeps a write descriptor to `staging/<v>/neoteletext`, outlives the browser, and writes its payload once the path reads `versions/<v>/…`; the launcher execs that file unconfined (`start.rs:27–36`). Effect: Linux, unconfined code as the user from a sandboxed helper, the release signature bypassed; macOS, modified code pages are refused by the kernel, so a failed trial marked bad, plus any non-code file of the bundle. Fix: do on Linux and macOS what `copy_in` does on Windows — `files::copy_tree` the staged folder to a place the updater's sandbox cannot open (`versions/<v>.copying` on Linux; outside `staging/` on macOS), run `accept` again on the copy, then rename/exchange the copy; secondarily kill the broker's process group when the broker exits.

### B2 — Medium: anything that can create a folder under `staging/` marks future versions bad, persistently
`launcher/src/lib.rs:267–281` (`prepare`): every candidate refused for any reason gets `state.mark_bad(candidate)`; candidates are folder names parsed as versions under `staging/` and `versions/` (`lib.rs:300–315`). A bad version is never offered (`core/src/updates.rs:302`) nor accepted (`lib.rs:310`); `MAX_BAD` 32 keeps the largest. A compromised updater (the one sandboxed process allowed to write `staging/`) does `mkdir staging/0.2.1 … staging/1.0.0`; at the next start they are all marked bad, said only on stderr. Effect: a freeze on genuine releases that outlives the compromise and TUF's 7-day expiry; the remedy is deleting the state file. Fix: delete the folder on refusal (line 277 already does) and do not mark bad, or mark bad only after `signer.check` passed; say the refusal in the panel; update `launcher/tests/launcher.rs:255–264`.

### B3 — Medium: closing the phone panel blocks the trusted core's one thread
Design: the core never waits on a helper (security-analysis.md 5.3; decision 53). `core/src/main.rs:1806–1812` `phone_panel(false)` drops the helper's stdin and then `let _ = child.wait();` on the event thread. `keyboard/src/keyboard.rs:48` calls `Screen::create` (HTTPS POST then WebSocket connect, blocking, per-read timeouts only: 10 s connect, 15 s per read, DNS unbounded) before the stdin reader thread is spawned at line 61, so a closed stdin is not noticed until `create` returns. Hostile input: a relay that accepts TCP and trickles one byte per < 15 s; non-hostile: open the panel offline and close it at once. Effect: every tab and intent frozen for ~10–25 s offline, unbounded against a hostile relay. Fix: helper, spawn the stdin reader before `Screen::create` and exit when stdin closes before the screen exists; core, never `wait()` on the event thread — let the reader thread's `PhoneEnded` reap, kill after a short grace.

### B4 — Low: a phone key name with a hidden character ends the browser (probe)
`protocol/src/keyboard.rs:134–137` `clean_name` refuses only `char::is_control`; the core forwards `FromKeyboard::Key { name }` as `ToInterface::PhoneKey(PhoneKey::Key { name })` without `clean()` (`core/src/main.rs:1878–1880`; contrast line 1882 for `Text`); `push_phone_key` uses `push_text`, which refuses U+200B–200F, U+202A–202E, U+2060–2064, U+2066–2069, U+FEFF, U+061C; a failed `send` ends the core's loop (`main.rs:2307–2311`). Probe (`…/A4-probes/browser/phone-key`): `FromKeyboard::Key { name: "a\u{200B}" }` (also `"Enter\u{FEFF}"`, `"\u{202E}Esc"`): `write_to_core` Ok, `read_from_keyboard` Ok, `write_to_interface(PhoneKey::Key)` → `Err(BadValue("text not cleaned"))`. Reach: the engine's screen forwards only keys of the fixed layout (`neoteletext-qrkeyboard/src/screen.rs:461–469`), so only a compromised keyboard helper can send such a name; it escalates "the phone keyboard stopped" into "the browser closed". Fix: `clean(&name, MAX_KEY_NAME)` at `main.rs:1879` and refuse an empty result, or make `clean_name` use `interface_core::editor::hidden`.

### B5 — Low: a page, bundle or form answer of exactly 262 144 bytes kills its channel's fetcher (probe)
The engine accepts a body up to and including `page_limit` (`neoteletext-web/src/http.rs:472` `length > limit`, `:505` `received > limit`), `DEFAULT_PAGE_LIMIT = 256 × 1024`; the fetcher uses `Config::default()` (`fetcher/src/main.rs:247`); `protocol/src/fetcher.rs:334` refuses `bytes.len() >= MAX_PAYLOAD` because the origin byte makes the payload one longer; the const assertion at `fetcher/src/main.rs:68` covers only `MAX_EXCHANGE_URL`. Probe: `write_to_core(FromFetcher::Page { bytes: vec![b'x'; 262143] })` Ok; 262 144 bytes → `Err(TooLong(262144))`. Effect: the fetcher's `run` returns Err, the process exits, the core removes it (`main.rs:2182–2192`): that channel's pages and push are gone until reload; a legitimate bundle of exactly that size takes its own channel down. Fix: `page_limit: protocol::MAX_PAYLOAD - 1` in the fetcher's `Config` and `const _: () = assert!(DEFAULT_PAGE_LIMIT < protocol::MAX_PAYLOAD)`; a regression test writing a `DEFAULT_PAGE_LIMIT`-byte page.

### B6 — Low: `ReachedQuestion` answers for any host, across channels and jars
`core/src/cookie_control.rs:117–120` answers `reached_securely(&host, now)` with no check that `host` is the asking channel's; `core/src/cookies.rs:256–261` searches both the ordinary and the private jar. `CookieQuestion`, `CookieSet` and `ClearSiteData` are correctly bound to the owner channel (`cookies.rs:107–109`, `232–234`, `248–250`). A compromised fetcher asks for a list of hosts and learns one bit per host (a live `Secure` cookie there) and private-tab state. Fix: answer `false` unless `host == owner.host`, and consult only the asking tab's jar.

### B7–B12 — Low (reported by the delegated reader, lines cited, not re-run)
- **B7** `fetcher/src/transport.rs:167–180`, `215–217`, `375–382`: the connecting thread has no overall deadline (`to_socket_addrs` unbounded, 10 s per resolved address, a per-read TLS timeout that restarts on every byte) and `Tcp::close` only shuts a `Link::Open`; a server with many never-completing addresses accumulates threads and 16 KB buffers in that channel's fetcher. Fix: one deadline per `open`, a cloned stream in `Link::Connecting` so `close` can shut it.
- **B8** `core/src/history.rs:167–175`, `restore.rs:248–250`, `bookmarks.rs:164–166`, `settings.rs:207–209`: one `String` in `dropped` and one `eprintln!` per bad line; a 16 MiB `history.txt` of newlines is ~16 M strings before the window opens; same-user writer only. Fix: cap `dropped`, skip empty lines, cap rows during read.
- **B9** `core/src/address.rs:163`, `:207`, `:42`: the canonical text can exceed `MAX_ADDRESS` after `https://`, `/` and `#NNN` are added, and every store re-parses and refuses it — a 2045–2048-byte address loses its visit, star and restored tab. Fix: bound the built text; make `with_page` fallible.
- **B10** `core/src/bookmarks.rs:433–449`, `457–487`: Undo of a removed folder does not check depth; the subtree is written past `MAX_DEPTH` and refused at the next read (data loss, no panic). Fix: compute the subtree's height in `restore`.
- **B11** `launcher/src/lib.rs:204–205`, `211–227`: with an unparsable state the newest complete version becomes `current` with hashes only and no trial, so decision 15's rollback does not protect that start; a state over 2 KiB (`InvalidData`) stops the browser starting, against security.md 4a "an unreadable one is rebuilt". Fix: `accept` with the signer in `recovered`, `current = older, trial = newest`, treat `InvalidData` as a refused parse.
- **B12** `tuf/updater/src/transport.rs:157`, `:35`, `:91–92`: every body is buffered to 64 MiB + 64 KiB before tough's 1 MiB/10 MiB limits apply, with per-read timeouts only; a trickling host keeps the updater busy indefinitely. Denial only; integrity is tough's. Fix: a size by URL and a total deadline per request.

## 4. qrkeyboard relay client and the input protocol

### 4.1 `neoteletext-input` (INPUT.md v2)

**Checked and sound.** `wire::Reader::uv`: at most 5 bytes, bits beyond 32 refused (`checked_shl`/`checked_shr` round trip), non-minimal forms refused (a trailing zero group), `Incomplete` distinct from malformed; `str` length checked against the field's limit before `take`, UTF-8 validated. `event::read`: text runs end at the next 0xFF, bytes 0xC0, 0xC1, 0xF5–0xFF refused, UTF-8 validated with a cut final character treated as "more needed", C0/C1/DEL refused in text (§5.3) but allowed in PASTE (§5.4, by design, "data, never keystrokes"); reserved types 0x00, 0x0B–0x3F, 0x80–0xFF refused; reserved flag bits refused; MOUSE/WHEEL cells bounded by 72×25; RESIZE non-zero and bounded; COMPOSE cursor ≤ the preedit's code points; HELLO agent printable ASCII ≤ 64; PAGE 0 or 0x100–0x8FF; extensions bounded by `MAX_MESSAGE` and skipped. `cursor::from_body`: every rule of §7.1 (page range, row 1–23 or 255 with column/width/flags 0, column < 40, column + width ≤ 40, ECHO needs width, MASKED needs ECHO, unknown flags refused). `control::read_body`: body ≤ 26 bytes (one fragment; a fuzz-found over-read is regression-tested), caps ⊆ `ALL_CAPS`, modes ⊆ `ALL_MODES`, page checked, nothing after the message. `session`: WELCOME only while waiting, version must be 2, caps must be a subset of what was offered, else `Refused`; acknowledgements by RFC 1982 serial arithmetic so an old or absurd `acked` changes nothing; mode stack 16 deep dropping the oldest; `POP_MODE` with any count saturates; the 120/s limiter counts units and never blocks a release. `write` reads its own output back before sending. Fuzzed (`input_stream`, `cursor_records`, `control_records`).

**Info.** The reader tolerates a message that ends inside a UTF-8 character (waits for more), where §5.1 says a message MUST hold whole characters; a lenient receiver is the safe side.

### 4.2 `neoteletext-qrkeyboard`

**Checked and sound.** All HTTP heads and WebSocket frames go through the engine's bounded readers (`net.rs`): heads ≤ 16 KiB, bodies ≤ 64 KiB, frames ≤ 1024 bytes (`MAX_FRAME_BYTES`), four 4 KiB reads buffered ahead of the owner at most, TLS by rustls with Mozilla roots and the host name checked, the relay's WebSocket must be on the relay's own host and scheme (`screen.rs:160`). Relay JSON through the engine's reader with ≤ 16 depth and ≤ 4096 values (`json.rs`); join code exactly 16 base-32 symbols; owner token ≤ 64. Sealed frames: tag, 4 zero bytes, 64-bit counter, AES-256-GCM with the full 16-byte tag; counters accepted only strictly increasing and advanced only after authentication, so a forged frame cannot burn a counter and a replay or reorder is dropped (`crypto.rs:126–145`); the sealer stops at 2⁶⁴. SPAKE2 per RFC 9382 with M/N, the identity and off-curve points refused as shares, the transcript binding code, configuration hash and both shares, confirmation compared in constant time, five PIN attempts then lock, and a phone that abandons a run after taking a share still counts an attempt. Phone messages: tag 0x10, plaintext ≤ 1024 − 29, an 11-character id, `count` clamped to 1…10 000, unknown keys of the layout ignored, duplicates acknowledged from a 256-entry cache without acting twice, held keys released after 15 s.

**Info.** `Stream::read` maps a TLS `UnexpectedEof` (no `close_notify`) to a clean close (`net.rs:160–163`), so a close-delimited HTTP body cut by the network is accepted as complete (`finish_at_close`); the relay's answers are `Content-Length`-framed JSON in practice, and a cut JSON document fails to parse.
